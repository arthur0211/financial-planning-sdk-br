# ADR 0009 — host-trust do diagnóstico AppContainer

**Estado:** candidato técnico remediado; novo freeze e crítica independente pendentes
**Data:** 2026-08-11

## Contexto

O spike local observa token/profile/classic behavior de um processo AppContainer sem integrar a matriz instalada do ADR 0008. Seu envelope é deliberadamente `not_counted`.

A primeira versão aceitava `--pwsh` e `--windows-powershell`. As checagens de `$PSHOME` viviam nos próprios drivers, portanto pertenciam ao mesmo host não autenticado que deveriam restringir. Um EXE benigno fornecido nesses argumentos ignorou os `.ps1`, escreveu outputs iniciados por `MZ`, emitiu o JSON canônico esperado e obteve RC0/`observed_pass` sem chamar API AppContainer. Hashes de outputs e validação de protocolo não distinguiam execução real de fabricação coerente.

A boundary precisa preceder qualquer subprocesso e permanecer ativa durante toda a invocação. Ela não pode descobrir WindowsApps por padrão de nome de pasta: uma pasta chamada `Microsoft.PowerShell_*_8wekyb3d8bbwe` não prova package identity instalado. Também não pode criar um signer ou receipt candidato, pois isso confundiria trust local do host com autenticação externa de evidência.

O freeze R8 fechou o host substituto, mas não a proveniência dos inputs/outputs temporários. Um watcher same-token esperou a cópia de `Program.cs`, `TokenProbe.cs`, cada driver, DLL ou EXE, trocou o arquivo antes do consumidor e obteve RC0 com JSON coerente, enquanto o report preservava o hash legítimo do checkout. Abrir um placeholder depois da compilação também deixaria uma janela entre o close do compiler e o novo lock; hashear o output já trocado ligaria bytes forjados ao report sem provar derivação source→output.

O freeze `db5c12cd…` fechou esses arquivos, mas ainda iniciou o driver com nomes PowerShell nominalmente resolvíveis. Um `Microsoft.PowerShell.Utility` em `PSModulePath` CurrentUser/TEMP-first substituiu `ConvertFrom-Json`, trocou o source legítimo por C# forjado e emitiu o helper JSON esperado. O wrapper aceitou RC0/`observed_pass`, stderr vazio e TEMP final limpo. Qualificar nomes também não fecha a classe: função ou alias previamente carregado pode usar o mesmo nome qualificado. A cadeia precisa ficar livre de `CommandAst` antes de qualquer autoload e ligar os bytes efetivamente compilados e executados ao request/report.

O freeze R10 `50c4ad6b…` também foi invalidado. O frame stdin externo era chamado de canônico, mas `JsonDocument.Parse` aceitava espaço inicial/final e ordem alternativa de chaves; a bootstrap não reconstruía os bytes nem reportava o digest raw observado pelo child. Um runner privado prefixou exatamente um espaço ASCII, o processo executou o AppContainer real e retornou RC0/`observed_pass`, enquanto `bootstrap_input_sha256` continuou descrevendo somente os bytes do produtor. O request interno tinha a mesma simetria lexical, e um hash declarado dentro do próprio frame não impedia substituir request + hash antes de `ScriptBlock.Create`. Equivalência semântica do JSON e consistência autorreferente não constituem binding de transporte.

## Decisão

O CLI `run_windows_appcontainer_spike.py` aceita somente `--temp-root` e `--timeout-seconds`. A função pública Python também não aceita paths de host, platform, runner ou nonce. Injeção de lease/runner existe apenas na função interna `_run_spike` para testes; ela não é superfície de evidência nem opção CLI.

A boundary `windows_host_trust.py` adquire os dois hosts sem `PATH`, variável de ambiente ou glob:

1. Windows PowerShell 5.1 é exatamente `WindowsPowerShell\v1.0\powershell.exe` sob o path retornado por [`GetSystemDirectoryW`](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemdirectoryw).
2. PowerShell 7 MSI é exatamente `PowerShell\7\pwsh.exe` sob `FOLDERID_ProgramFiles`, obtido por [`SHGetKnownFolderPath`](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath).
3. Se o MSI não existe, a família `Microsoft.PowerShell_8wekyb3d8bbwe` é consultada por [`GetPackagesByPackageFamily`](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getpackagesbypackagefamily). Cada resultado é reconciliado por [`PackageFamilyNameFromFullName`](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-packagefamilynamefromfullname), [`PackageIdFromFullName`](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-packageidfromfullname) com informação completa e [`GetPackagePathByFullName`](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getpackagepathbyfullname). Nome, publisher DN/ID Microsoft, arquitetura, versão e o único diretório direto sob `Program Files\WindowsApps` precisam coincidir. O `pwsh.exe` precisa existir nesse diretório. Regex serve apenas para reconciliar o full name devolvido pelo OS; nunca enumera nem descobre pasta.

Para cada componente da cadeia, inclusive executável, a boundary:

- abre um handle com `FILE_FLAG_OPEN_REPARSE_POINT`, recusa atributo reparse e confere tipo, path final e a identidade de 128 bits de [`FILE_ID_INFO`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info), combinada ao volume serial de 64 bits;
- exige owner SYSTEM, TrustedInstaller ou Administrators;
- tenta abrir, sob o token corrente, os direitos de write/alteração, delete/delete-child, `WRITE_DAC` e `WRITE_OWNER`; sucesso reprova e erro diferente de access denied é indeterminado/falha;
- readquire o mesmo objeto e mantém um handle com share-read apenas. Isso bloqueia writers e renames/deletes concorrentes enquanto os hosts são usados;
- confere SHA-256 e versão de arquivo sob a lease. Para MSIX, full name e package version precisam coincidir, e os três primeiros componentes da versão do executável precisam coincidir com o pacote; o quarto componente pode representar revisão de build distinta;
- chama [`WinVerifyTrust`](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust) com `WINTRUST_FILE_INFO` ligado ao handle. Para binário inbox sem assinatura embutida, calcula o hash do mesmo handle, localiza o catálogo por `CryptCATAdmin*` e usa `WINTRUST_CATALOG_INFO`. O signer leaf precisa ter organização `Microsoft Corporation` e common name fechado Microsoft. A política é deliberadamente offline/cache-only e usa `WTD_REVOCATION_CHECK_NONE`: ela não busca estado atual de revogação nem prova freshness da cadeia.

O volume root também é verificado por reparse, owner, identidade, alteração direta, delete/delete-child, DACL e owner, e permanece com handle bloqueado. O acesso comum para criar um novo sibling na raiz do volume não é interpretado como capacidade de substituir o filho protegido já existente e não sustenta claim de “volume root read-only”. Administrador, kernel ou base de trust comprometidos permanecem fora do modelo.

A lease dos dois hosts fica aberta durante a única chamada e revalida handles, owners, paths, IDs, hashes e versões imediatamente antes/depois do subprocesso. A invocação usa somente os paths vindos das identidades adquiridas.

O envelope passa a `finplanbr.windows-appcontainer-spike-wrapper.v5`; o helper permanece `finplanbr.windows-appcontainer-token-spike.v2`; o request passa a `finplanbr.windows-appcontainer-spike-request.v5`, que inclui `finplanbr.windows-appcontainer-input-binding.v3`. O transporte interno usa bootstrap input v2, input in-memory v2 e driver output v2. Report e request incluem para cada host path absoluto, file ID, SHA-256, file version, publisher, signer, perfil de instalação e, no MSIX, full name/publisher/version. Mudar qualquer identidade muda o digest de request ou falha antes da execução.

`Program.cs` é o único source runtime. O Python abre o arquivo do checkout uma vez com share-read apenas e `OPEN_REPARSE_POINT`, lê, hasheia e consulta `FILE_ID_INFO` pelo mesmo handle, revalida digest/identidade antes e depois do consumidor e mantém o handle aberto durante toda a chamada. Uma tentativa preexistente de write impede a lease; write, rename ou delete durante a lease falham. O digest, file ID e path relativo fechado entram no input binding.

Uma bootstrap curta e request-specific cabe no limite de 32.767 caracteres de `CreateProcess` via `-EncodedCommand`. Seus dois placeholders fixam os SHA-256 esperados do driver e do request interno antes do subprocesso. Driver UTF-8 e request seguem juntos no bootstrap input v2. Esse frame aceita somente os cinco campos ASCII fechados, em ordem `driver_base64`, `driver_sha256`, `format`, `request_base64`, `request_sha256`, JSON compacto e exatamente um LF final. A bootstrap lê bytes do stdin do OS, faz UTF-8 estrito, rejeita chaves duplicadas/extras, exige hash lowercase e round-trip Base64, reconstrói `fpbr-json-ascii-fixed-order-lf.v1` byte a byte e exige igualdade integral antes de `ScriptBlock.Create`. Espaço inicial/final, ordem alternativa, CRLF, linha extra ou representação alternativa falham; trocar request + hash também falha contra o digest embutido na bootstrap.

A própria bootstrap aplica a mesma reconstrução ao input in-memory v2 antes de criar o `ScriptBlock`, com ordem fixa `format`, `moniker`, `program_cs_base64`, `program_cs_sha256`, `suspended_image_utf8_base64`, `work_root_utf8_base64` e um LF; o driver repete a defesa antes de Roslyn ou helper. Paths arbitrários são bytes UTF-8 estritos transportados como Base64 canônico, de modo que o frame permanece no subconjunto ASCII fechado e não depende de diferenças de escape Unicode entre serializers. A bootstrap calcula o SHA-256 dos bytes raw decodificados do request; o driver compara esse valor ao round-trip recebido e reporta, no driver output v2, `observed_bootstrap_input_sha256` e `observed_in_memory_input_sha256`. O Python exige igualdade deles com os dois hashes do produtor antes de aceitar o envelope. Os digests incluem o LF final e distinguem frame externo raw, request interno raw, bootstrap instanciada, driver, `Program.cs` e stdout.

Bootstrap e driver têm como primeira instrução `$PSModuleAutoLoadingPreference = 'None'`, parseiam sem erros e com zero `CommandAst`; depois da checagem de política também esvaziam `PSModulePath` no processo. Parsing estrutural por `System.Text.Json` não autoriza equivalência lexical: somente a reconstrução byte-exata decide a admissão. Módulo, função ou alias do usuário não participa de parsing, compilação, comparação ou output. O processo precisa estar em `FullLanguage` e `SystemPolicy` lockdown `None`; CLM, audit/enforcement, API ausente ou incompatível falha sem fallback para `Add-Type` ou CodeDOM.

O JSON estrito é processado por `System.Text.Json`. O driver usa Roslyn já disponível sob o `$PSHOME` aceito e fecha as referências TPA ao mesmo `$PSHOME`: paths ordenados canonicamente, sem reparse, streams share-read-only, hash antes de `ModuleMetadata(..., leaveOpen=true)` e rehash depois do emit. O digest do roster ordenado entra no envelope. O PE nasce em `MemoryStream`; o SHA-256 é calculado sobre exatamente o mesmo `byte[]` passado a `Assembly.Load`, e `Program.Entry` vem por reflection da assembly retornada, nunca do tipo global `[Program]`. O stdout do helper é capturado e codificado dentro de um envelope externo canônico, validado pelo Python antes do JSON interno. Bootstrap, driver, source compilado, DLL e EXE não são persistidos e não existe output compilado a relock.

A boundary do executável e da cadeia protegida de `$PSHOME` impede alteração same-token modelada, e o digest do roster liga os bytes de referência realmente consumidos. Ela não transforma o SHA do `pwsh.exe` em autenticação criptográfica de cada sibling nem estabiliza para sempre APIs internas do PowerShell/Roslyn; mudança de capability deve falhar fechado. Administrador, updater privilegiado, engine, memória do processo ou runspace/type data já corrompidos permanecem fora da claim.

O helper in-memory cria o `powershell.exe` inbox protegido como AppContainer suspenso e nunca o retoma. O parent lê o process token externamente, cria um token de impersonation por [`DuplicateTokenEx`](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-duplicatetokenex), usa [`ImpersonateLoggedOnUser`](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-impersonateloggedonuser) para observar read+SHA no arquivo com All Application Packages e `CreateFileW` access denied no controle sem AAP, chama `RevertToSelf`, termina o child ainda suspenso e faz a prova delete/recreate/delete do profile. O report contém somente `process_token`; não recebe self-report de um child.

`TokenProbe.cs`, o `.csproj` e quaisquer drivers históricos podem permanecer como material auxiliar não consumido, mas saem do roster, input, request e claim. Depois do helper, TEMP precisa conter exatamente o diretório `work` vazio e não-reparse; os dois arquivos de dados AAP/no-AAP são apagados antes do stdout. Qualquer outro nome — inclusive os sete targets históricos ou um nome aleatório — falha `temporary_code_artifact_detected` antes de decodificar/promover o report, e o cleanup remove toda a raiz por nonce. Essa é somente evidência `absent_at_final_inventory`: um watcher observou o próprio PowerShell criar e apagar `__PSScriptPolicyTest_*.ps1/.psm1` como probes de application control. O report usa `final_inventory_only_transient_activity_not_observed`, não “nunca criado”, e leftovers não recebem whitelist.

Falhas usam somente status/reason fechados e não incorporam exceção ou path rejeitado. Um `observed_pass` exige retorno zero do helper; o teste opt-in real exige exatamente RC0 e `status=observed_pass`, nunca RC1.

## Consequências

O PoC por host substituto morre no parser como RC2 antes de criar pasta temporária ou output. Paths inesperados, pacote/publisher/versão divergentes, reparse, owner, ACL, assinatura, hash e identidade instável falham antes da compilação in-memory. O PoC watcher deixa de ter source/driver/DLL/EXE temporário para substituir; se plantar qualquer entry na raiz TEMP fechada, recebe RC1 e cleanup verificado. Tentativas de write/replace contra uma cópia segura de `Program.cs` durante a lease são bloqueadas, e writer preexistente impede a execução antes do runner. O PoC `PSModulePath` possui controle positivo que executa o módulo malicioso, mas a bootstrap/driver exata produz o envelope legítimo sem marker; funções/aliases qualificados e um `Program` conflitante previamente carregados também não decidem a execução. O runner real que prefixa stdin com um espaço agora recebe RC1 antes do driver/helper; controles diretos cobrem whitespace, ordem, CRLF, multiline, duplicatas, extras, Base64/hash não canônicos e substituição autorreferente do request nas duas camadas.

O report fica mais explicável e reexecutável porque identifica exatamente os hosts e os bytes de transporte observados que sustentaram a observação. Isso não autentica quem executou o Python nem a origem do JSON; hashes e WinVerifyTrust são dados produzidos pelo candidato sobre primitives do host. O estado continua `portability_cell=not_counted`, `diagnostic_only=true`, `evidence_authentication=not_implemented`, `authority=none`, `release_authorized=false`; network/filesystem/job/handle isolation e packaging além do slice permanecem `not_evaluated`. A remediação é evidência builder e continua pendente de freeze novo e crítica independente; não estabelece PASS.

A boundary depende de Windows, AppModel, catálogo/WinTrust, ACLs e trust store locais. Host sem PowerShell 7 suportado é `not_observed`; assinatura/publisher ou access check indeterminado é falha. Como a validação é cache-only sem revogação, certificado revogado depois da informação local disponível pode não ser detectado. O controle não afirma resistência a administrador, kernel, engine PowerShell, interpreter Python, catálogo, cache ou trust store comprometidos.

## Alternativas rejeitadas

- manter overrides e validar `$PSHOME` dentro dos `.ps1`, porque o host substituto controla essa validação;
- aceitar `Get-Command`, `PATH`, environment override ou busca recursiva, porque ampliariam descoberta para paths controláveis;
- inferir package identity do nome de diretório WindowsApps, porque o nome pode ser fabricado sem registro AppModel;
- copiar o host validado para TEMP, porque a cópia perde a cadeia protegida e a identidade assinada/locked usada na decisão;
- validar assinatura por PowerShell `Get-AuthenticodeSignature`, porque isso delegaria a boundary ao host cuja identidade está sendo estabelecida;
- aceitar somente assinatura embutida, porque `powershell.exe` inbox pode ser assinado por catálogo Windows;
- hashear hosts uma vez e fechar handles antes do subprocesso, porque reabre TOCTOU de path/conteúdo;
- copiar sources, drivers ou outputs compilados para TEMP e relocká-los entre fases, porque cada close/reopen reabre a corrida e um hash pós-troca não prova derivação;
- importar `Microsoft.PowerShell.Utility` por path protegido ou apenas qualificar `Add-Type`/JSON/helpers, porque funções e aliases já carregados ainda vencem resolução nominal;
- continuar com `Add-Type`, porque ele é um cmdlet autoloadable e não expõe os bytes PE exatos para o binding `hash → load → entrypoint`; usar CodeDOM como fallback, porque a API existe mas não é suportada no .NET Core observado;
- enviar o driver completo por `-EncodedCommand`, porque sua linha ultrapassa o limite Windows de 32.767 caracteres; materializá-lo por `-File` reabriria a corrida evitada;
- manter um `TokenProbe.exe` ou pedir ao child que compile/se autorrelate, porque isso cria outputs substituíveis e delega a observação ao processo sob teste;
- manter o `.csproj` no request sem consumi-lo, porque isso criaria uma claim falsa de input;
- promover o spike a célula de portabilidade ou fabricar receipt local, porque a origem da evidência continua não autenticada.
